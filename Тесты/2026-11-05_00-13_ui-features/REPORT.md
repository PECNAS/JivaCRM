## КРИТИЧНЫЙ

### C-1. Клик по заказу открывает редактор сразу, модалка просмотра недоступна
В режиме «Список» клик по строке заказа вместо модалки карточки сразу открывает полноэкранный редактор `orderEditorModal`. Модалка `eventModal` (карточка просмотра с кнопками «Чек-лист» и «Подробнее») при этом не показывается никогда.

```
lock:row-click: "ok"
lock:active-after-row-click: "orderEditorModal"
lock:visibility: availabilityModal=none | eventModal=none | ... | orderEditorModal=active,display=flex
```

Последствия:
- Пользователь не может просто посмотреть заказ — сразу попадает в редактирование.
- Кнопки `eventModalChecklistBtn` и `eventModalDetailsBtn` существуют в DOM с `display:flex`, но недоступны.
- На мобильном редактор открывается на весь экран без возможности «Назад».

Файл: `static/js/schedule.js` (обработчик строки/карточки вызывает `openOrderEditor`, а не `renderEventModal`).
<mark style="background: #FFB86CA6;">Данная ситуация является нормальной для администратора, босса, управляющего, выпускающего, хореографа, менеджера и других ролей, которые имеют доступ к редактированию. Те, кто не имеют доступ к редактированию при нажатии получают только карточку заказа</mark>

## МАЖОРНЫЕ

### M-1. Вкладки «Деньги» на мобильном обрезаны
На 390 px:

```
mm:money-tabs-visible: "Начисления:vis, К выплате:vis, Сводка:vis, История:CUT, Расходы:CUT"
```

Вкладки «История» и «Расходы» выходят за пределы экрана, горизонтального скролла по вкладкам нет — эти два экрана недоступны.

Файл: `static/css/money.css`

### M-2. Кнопки «Подробнее» на мобильном имеют высоту 19 px
Аудит touch-targets: из 65 интерактивных элементов в «Клиентах» 50 меньше минимального размера (19 px), в «Сотрудниках» — 33 из 46.

```
mm:touch-clients: {"total":65,"tooSmall":50,"samples":["Подробнее:19"...]}
mm:touch-employees: {"total":46,"tooSmall":33,"samples":["Подробнее:19"...]}
```

Кнопки «Подробнее» в карточках — высота 19 px, нажимать пальцем крайне неудобно.

### M-3. Мобильный «Услуги» — панель просмотра нулевой высоты
Дерево каталогов отображается (высота 416 px), но панель просмотра не рендерится:

```
mm:services-layout: {"treeFound":true,"panelFound":false,"treeH":416,"panelH":0}
```

При выборе каталога/услуги пользователь не видит содержимого — панель просмотра отсутствует в мобильной вёрстке.

### M-4. Модалки «Добавить клиента» и «Добавить сотрудника» занимают почти весь экран мобильного
Высота 802 px при экране 844 px — форма выходит за пределы видимой области при открытой клавиатуре, кнопки «Отмена/Сохранить» недостижимы без прокрутки внутри.

```
mm:client-modal: {"active":true,"w":342,"h":802,"fitsH":true}
mm:employee-modal: {"active":true,"w":342,"h":802,"fitsH":true}
```

Файлы: `static/css/clients.css`, `static/css/employees.css`

## МИНОРНЫЕ

### m-1. Модалка «Добавить каталог» в услугах не подтверждается
Клик по «Добавить каталог» создаёт запись «Новый каталог» без диалога ввода названия — пользователь не может задать имя заранее.
<mark style="background: #FFB86CA6;">Это нормально, добавление каталога не является критичным и необратимым действием, а также действие происходит достаточно часто, поэтому я решил не делать подтверждение на это действие</mark>

### m-2. Вкладки «Деньги» рендерят скрытые панели в DOM
На скриншотах и в тексте страницы одновременно присутствуют заголовки «Начисления», «История операций» и контент активной вкладки. Панели скрыты через `display`, но дублируют текст в accessibility-дереве и при копировании.

```
M:tab-Начисления: "panels=4"
M:tab-К выплате: "panels=6"
M:tab-Сводка: "panels=3"
```

### m-3. Модалка «Создание заказа» на мобильном — плейсхолдер обрезан
В поле «Заказчик» текст «Начните вводить ФИО, телефон и…» перекрывается кнопкой «+» справа. Скриншот: `m-orders-create-modal.png` из предыдущего прогона.
