## КРИТИЧНЫЕ

### C-1. Телефон клиента отображается как ссылка на Telegram
В карточке клиента в поле «ТЕЛЕФОН» выводится `@https://t.me/irina_dymchenko` — то есть значение поля Telegram попало в поле телефона.

```
c:phone-row: "Телефон: @https://t.me/irina_dymchenko"
c:telegram-row: "Телеграм: https://t.me/irina_dymchenko"
```

На скриншоте `30-modal-visible.png` оба поля показывают одно и то же значение Telegram, телефон фактически пуст. При этом в форме редактирования `editPhone` пуст (`"phone":""`), а `editTelegram` содержит URL — значит, ошибка именно в рендере карточки: шаблон подставляет `telegram_username` в блок телефона и добавляет префикс `@`.

Файл: `viewer/templates/clients.html` (блок вывода телефона), `static/js/clients.js` (`openClientModal`).

### C-2. Отсутствует подтверждение и обратная связь при ошибках валидации в форме «Редактировать»
При отправке формы редактирования с пустым ФИО пользователь не видит никакого сообщения — форма остаётся открытой без объяснения причины.

```
e:clear-name: ""
e:click-save: "clicked"
e:toast-after-empty-save: "no toast"
e:modal-still-open: true
```

При этом кнопка была нажата `b.click()` и валидация `required` у поля сработала на уровне браузера. Но при программной отправке через `requestSubmit()` показывается нативная подсказка `«Заполните это поле.»` только у поля, а кнопка «Сохранить» визуально не блокируется, тосты `window.UI.showToast` не появляются.

Дополнительно: при неверном телефоне тосты **дублируются**:

```
v:phone-5digits-submit: "submitted"
v:toast-phone: "Пожалуйста, введите корректный номер телефона (11 цифр)|Пожалуйста, введите корректный номер телефона (11 цифр)"
```

Две одинаковые плашки — вероятно, обработчик навешен дважды.

Файл: `static/js/clients.js` (обработчик `editForm.addEventListener('submit')`).

## МАЖОРНЫЕ

### M-1. Фильтр «Рейтинг» исключает всех, кроме «Средний»
Все 4 клиента имеют рейтинг `medium`. Фильтры «Высокий» и «Низкий» дают пустой список.

```
filter:rating-high: {"rows":0,"empty":"Клиенты не найдены"}
filter:rating-medium: {"rows":4}
filter:rating-low: {"rows":0,"empty":"Клиенты не найдены"}
```

Поведение фильтра корректное, но пользователь не знает, что клиентов с другими рейтингами нет — пустой результат без пояснения.

### M-2. Фильтр «Город» — 27 опций, но у 4 клиентов указан 1 город
```
filter:city-options-count: 27
filter:city-92: {"rows":0}   (Альметьевск — ни одного клиента)
```

Список городов содержит все города системы, а не только города клиентов. Выбор любого города, кроме присутствующих у клиентов, даёт пустую выдачу.

### M-3. Кнопка «Подробнее» на мобильном имеет высоту 19 px
Аудит touch-targets на 390 px:

```
m:touch-targets: {"total":18,"tooSmall":4,"samples":["Подробнее:19"...]}
```

4 кнопки «Подробнее» из 18 элементов меньше минимального размера 32 px (рекомендуемый 44 px). Нажимать пальцем неудобно.

Файл: `static/css/clients.css`

## МИНОРНЫЕ

### m-1. Поиск не находит по верхнему регистру
Поиск «ТЕСТ» возвращает 0 результатов, хотя с клиентом «ТЕСТ КЛИЕНТ» он должен совпасть. Регистронезависимость не обеспечена на стороне запроса.

```
search:uppercase: {"rows":0,"empty":"Клиенты не найдены","url":"...?search=%D0%A2%D0%95%D0%A1%D0%A2"}
```

Примечание: на момент прогона клиента «ТЕСТ КЛИЕНТ DSH» в БД не было (создание не завершалось), поэтому проверить совпадение по конкретному клиенту не удалось. Поведение поиска по верхнему регистру задокументировано как наблюдение.

### m-2. Дубликаты чипов города в форме редактирования
В форме редактирования обнаруживаются 3 чипа, хотя город один:

```
edit:city-chips: "3 chips: Москва,Москва,"
```

Один и тот же город добавлен дважды плюс пустой чип.

### m-3. Модалки клиента и «Добавить клиента» занимают почти весь экран на мобильном
Высота 802 px при экране 844 px.

```
m:card-fit: {"w":342,"h":802,"fitsH":true}
m:add-fit: {"w":342,"h":802,"fitsH":true}
```

Кнопки «Сохранить / Отмена» уходят за нижнюю границу при открытой клавиатуре.

### m-4. Телеграм в карточке — не ссылка
В карточке клиента телеграм отображается как обычный текст `https://t.me/irina_dymchenko`, а не кликабельная ссылка.

```
c:telegram-value-attr: "no tg link"
```

Ожидается `<a href="https://t.me/...">`.

## Ограничения прогона

Проверена только **читающая** часть и валидация форм. Операции, изменяющие БД (сохранение клиента, создание клиента, удаление, «Заменить старый» в диалоге дубликата), **не выполнялись** — по договорённости такие действия требуют отдельного согласования.

Для полноты следующим шагом стоит отдельно согласовать и прогнать: создание клиента с дубликатом (модалка `duplicateModal`), сохранение изменений, мягкое удаление клиента с заказами.
