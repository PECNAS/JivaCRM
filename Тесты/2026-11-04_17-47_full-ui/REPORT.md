## КРИТИЧНЫЕ

### C-1. Мобильный календарь: сетка шире экрана, скролл заблокирован
На ширине 390 px сетка календаря имеет ширину 560 px при ширине контейнера 390 px. Горизонтальный скролл документа заблокирован (`overflowX: false`), поэтому колонки ПТ, СБ, ВС недоступны — включая 15 ноября, где стоят заказы.

```
scrollWidth: 390, clientWidth: 390, grid width: 560, cell width: 78.84
```

Файл: `static/css/schedule.css`

top: 01.11.20 — 30.11.20 (перекрыто иконкой календаря)

## МАЖОРНЫЕ

### M-1. Телефон в карточке клиента не маскируется
Поле ввода телефона в модалке «Добавить клиента» имеет id `addContact` (не `addPhone`), поэтому JS-маска `+7 (999) 123-45-67` к нему не применяется: ввод `79171234567` остаётся без форматирования. Значения на странице «Клиенты» тоже выводятся как `79872907757` без маски.

```
add-modal-fields: ...|addContact|addContactType|...
phone-mask: "nophone"  (поле с именем, содержащим "тел/phone", не найдено)
```

Файл: `viewer/templates/clients.html` / `static/js/clients.js`

### M-2. Модалка «Добавить клиента» на мобильном не влезает по высоте
Высота модалки 802 px при высоте экрана 844 px (без учёта безопасных зон браузера), контент прокручивается внутри. Кнопки «Отмена/Сохранить» уходят за нижнюю границу при открытой клавиатуре.

```
m-client-modal-fit: {"w":342,"h":802,"fitsW":true}
m-employee-modal-fit: {"w":342,"h":802,"fitsW":true}
```

Файл: `static/css/clients.css`, `static/css/employees.css`

### M-3. Кнопка «Создать заказ» на мобильном стоит выше поиска и фильтров
На `/orders/`/`/schedule/` кнопка идёт первой в потоке, затем поиск, затем фильтры. На десктопе порядок обратный. Ожидаема единая последовательность: фильтры → результаты → кнопка действия.

### M-4. Мобильное меню перекрывает контент без backdrop
При открытом бургер-меню под ним виден календарь, но нет затемнения фона и нет закрытия по клику вне меню — только по крестику. Скриншот: `m-menu-open.png`.

Файл: `static/css/base.css` / `static/js/menu.js`

## МИНОРНЫЕ

### m-1. Пустое состояние календаря при поиске без совпадений
В режиме «Календарь» при поиске, не давшем результатов, сетка отображается пустой без сообщения «Ничего не найдено». Пользователь не понимает, что фильтр активен.

### m-2. Вкладки «Деньги» перекрывают друг друга в DOM
На скриншотах `verify-money-*` видно, что при переключении вкладок панели предыдущей вкладки остаются в DOM и рендерятся «поверх»: в панели «Сводка» присутствует заголовок «Начисления», в «Расходах» — «История операций». Визуально невидимы (по `display`), но дублируют текст в accessibility-дереве и при копировании страницы.

Проверка:
```
money-tab-Сводка content: "money-panel__head=Начисления Ждут н... || money-panel__head=История операций..."
```

### m-3. Плейсхолдер в модалке «Создание заказа» обрезан на мобильном
В модалке «Создание заказа» на 390 px плейсхолдер «Начните вводить ФИО, телефон и…» обрезан по правому краю под иконкой «+». Скриншот: `m-orders-create-modal.png`.

### m-4. Двойной клик по дате/адресу в модалке расписания не открывает inline-редактор
Причина в `canOpenOrders()` (`static/js/schedule.js:206`): роль `boss` не входит в список, хотя backend (`Employee.can_manage_orders`) для Босса возвращает `True`. Следствие — inline-правка даты и адреса недоступна.

### m-5. Иконки/кнопки в шапке на мобильном 23 px
Аудит touch-targets на 390 px показал 2 элемента высотой 23 px в шапке расписания и заказов (кнопки навигации по календарю и иконка профиля). Минимальный рекомендуемый размер 44x44.

```
m-touch-orders: {"total":15,"tooSmall":2,"samples":[":23",":23"]}
m-touch-schedule: {"total":15,"tooSmall":2,"samples":[":23",":23"]}
```

## ЧТО РАБОТАЕТ

### Авторизация и навигация
- Вход по логину/паролю, редирект на `/schedule/`
- Глобальное меню: Расписание, Клиенты, Сотрудники, Услуги, Деньги, Отчёты, Профиль, Выйти
- Активный пункт меню подсвечивается, иконка профиля ведёт на `/profile/`
- Мобильный бургер: меню открывается, все 6 разделов + «Профиль» и «Выйти» отображаются

### Расписание
- Календарь загружается, сетка 42 ячейки, подсветка текущего дня
- Навигация по месяцам без ошибок, включая границы года
- Карточки заказов открывают модалку с полями Название / Статус / Дата / Заказчик / Город / Адрес / Менеджер / Стоимость / Услуги
- Модалка закрывается крестиком и по Escape
- Контекстное меню на ячейке и на карточке: «Создать заказ / Создать тренировку / Отметить занятость / Создать событие»
- «Отметить занятость» открывает модалку с подставленной датой и списком сотрудников (32 записи)
- Режим «Список»: заголовки, данные, сортировки, фильтр статуса, поиск без учёта регистра, пустое состояние «Заказы не найдены»
- Переключение Календарь ↔ Список, выбор сохраняется в `localStorage` (`jiva_schedule_view`)
- Автообновление раз в 30 сек зарегистрировано (`window.refreshSchedule`)

### Клиенты
- 50 клиентов, пагинация/скролл, заголовки «ФИО | Телефон | Агентство | Города | Рейтинг | Запросов | Заказов»
- Поиск по ФИО/телефону/агентству фильтрует на лету: 50 → 2 («Айгуль»)
- Фильтры «Все рейтинги», «Все города»
- Модалка «Добавить клиента» открывается, поля: ФИО, Контакт, Тип контакта, Тип клиента, Агентство, Email, Город, Рейтинг, Комментарий
- Автодополнение агентства и города работает (AJAX `/agencies/catalog/`, `/clients/cities/`)

### Сотрудники
- 33 сотрудника, заголовки «ФИО | Логин | Роль | Телефон | Статус»
- Поиск фильтрует: 33 → 1 («Влад»)
- Модалка «Добавить сотрудника»: логин, пароль, ФИО, имя для обращения, 9 ролей, телефон, телеграм, РЖД-бонус, инстаграм, статус, загранпаспорт, паспорт, СНИЛС, ИНН

### Услуги
- Дерево каталогов отрисовывается, узлы раскрываются
- Кнопка «Добавить каталог» открывает редактор каталога с полями: название, ставка за артиста, таблица «Количество артистов / Стоимость»
- Кнопки «Сохранить» и «Удалить» на месте, тост «Создан каталог»

### Деньги
- Период с нативными датами, кнопки «Текущий месяц», «Назад/Вперёд»
- 4 сводные карточки: Начислено / Ждёт начисления / Выплачено / Баланс сотрудников
- Вкладки «Начисления», «К выплате», «Сводка», «История», «Расходы» — все переключаются, содержимое отображается
- «Сводка по сотрудникам» — таблица с колонками Ставка за заказ / Оклад / Часы и % / Суточные / Премия / Откат начисления / Вычет / Начислено / Выплачено / Баланс
- «Расходы» — фильтры «Все / На рассмотрении / Корпоративный счёт / Команда», пустое состояние «Расходов за период нет»

### Профиль
- Вкладки «Мои данные», «Деньги», «Доступность», «Билеты»
- «Мои данные»: личная информация и паспортные данные, кнопка «Редактировать» открывает модалку «Редактирование данных»
- «Доступность»: обычная неделя (7 дней), исключения на даты, календарь на месяц
- «Билеты»: список транспортных билетов
- Кнопка «Выйти из аккаунта»

### Заполнение данных
- Четыре карточки импорта: Сотрудники, Услуги, Клиенты, Заказы — с описанием полей
- Блок «Удаление данных» с предупреждением «Удаление необратимо»

### Мобильная адаптация
- Ни на одной странице нет горизонтального переполнения документа (`scrollWidth === clientWidth === 390`)
- Модалка «Создание заказа» — влезает полностью (342x714)
- Списки «Клиенты», «Сотрудники» — карточная раскладка
- Бургер-меню открывается/закрывается
